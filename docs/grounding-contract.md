# NOT A LM 接地契約（Grounding Contract）

この文書は、NOT A LM が目指す **コーパス完全接地の応答** についての契約である。  
実装詳細（G2–G7 の個別機構）より上位に置き、設計・減枝・API 整理の判断基準とする。

関連実装ドキュメント: [`grounded-generation.md`](grounded-generation.md) 以降の G 系、[`reranker-and-confidence-gate.md`](reranker-and-confidence-gate.md)。

---

## 1. 目的

LLM に近い **柔軟な応答** を、**コーパス内部のデータに完全に接地した形**で行う。

- **柔軟さ**: ユーザー入力と履歴に応じて、適切な断片の選び方・組み立て方が変わる。
- **完全接地**: 返答に現れる内容語は、コーパス（および明示した許可集合）からコピーされたものに限る。本質的な新規トークン／文の生成は行わない。

初期の「総当たり検索で近い `value` を返す」は出発点であり、最終形ではない。合成操作（分割・結合・並べ替え・閉じた糊）で返答を組み上げるが、自由生成はしない。

---

## 2. 「完全」（complete grounding）の定義

### 許可する出力の構成要素

返答文字列は、次の和集合からのコピー／組み立てのみで構成される。

| 許可 | 例 |
|------|-----|
| コーパス断片 | チャンク `value`、著者 `spans[]` の text |
| 履歴スパンのコピー | 直前 bot の grounding excerpt など（G6） |
| 閉じた糊（定型） | 言語別に列挙した否定／肯定オープナー、topic 接続、clarify 定型など |
| クエリ／履歴から抜いた topic | 融合時の「〜については、」の話題部分など（生成ではなく抽出） |

閉じた糊の範囲は **現状どおり**（コード上の閉じた集合）。  
「コーパス claim 化した定型のみにさらに締めるか」は **別途検討**（本契約の必須条件ではない）。

### 禁止

- コーパス／履歴／閉じた糊／抽出 topic にない **内容トークンの新規生成**
- 制約なしの seq2seq・LLM デコードによる返答本文の生成

### 用語

| 用語 | 意味 |
|------|------|
| **接地生成** | 上記の許可集合だけで返答を組み上げること。本プロジェクトの本線。 |
| **接地組み立て** | 接地生成と同じ本線を指す言い換え（生成モデルがないことの強調）。文書では **接地生成** に統一する。 |
| **as-is** | 接地生成の **結果ラベルの一種**。選んだチャンクの `value` を、否定オープナー・部分 KEEP・融合なしでそのまま返す場合。接地していない、という意味ではない。 |
| **合成操作** | 分割・結合・並べ替え・KEEP/DELETE・閉じた糊の挿入など。トークン生成ではない。 |

## 3. 単一ワークフロー

ユーザー入力を処理するルートは **基本的に一つ** である。

```
history + user text
  → 解釈（何についてか / 照応か / 複合か / コーパス外か）
  → 資源の選択（チャンク・スパン）
  → 組み立て（OperationPlan）
  → render（コピー + 閉じた糊）
  → grounding を残す
```

- 骨格は常に同じ。入力に応じて変わるのは途中の **判断結果** と、その結果としての `OperationPlan` の形である。
- **本線は常に接地生成**である。as-is も fuse も clarify も、同じワークフローの出口の違いである。
- API / UI の **mode やトグルで別パイプラインに入ること**は、目指す形ではない（初期実装の枝が露出した最悪ケース）。

### 本線にしないもの

| 現状の露出 | 契約上の扱い |
|------------|--------------|
| `mode: reply \| predict-user \| emit-claim \| chain-plan` | 本線の分岐にしない。解決は一つの応答器へ収束させる。 |
| `generate` トグル（接地 ON/OFF） | 本線は常に接地生成。OFF 専用ルートは本線に残さない。 |
| 連鎖デモの `emit-claim` 専用路 | デモは本線の連続呼び出しで表現する。 |

ワークフローの **外** に置いてよいもの（ユーザー発話の解釈ではないもの）:

- コーパス編集（G7）
- ステータス／モデルロード
- 連鎖の「どの順で本線を叩くか」を並べる薄いプランナー（各ターン自体は本線）

---

## 4. 柔軟さの実現方法

LLM 的な柔軟さは、**入力に応じて OperationPlan が変わること**で実現する。別 mode・別エンジンで実現しない。

結果として現れうる形の例（排他のスイッチではなく、組み立ての結果）:

- 全文コピー（as-is）
- 閉じた極性オープナー + 本文（negate / affirm）
- スパン単位の部分 KEEP（compose）
- 複数チャンクの接続（fuse）
- 閉じた聞き返し（clarify）
- コーパス外としての拒否（limit 系チャンク等）

---

## 5. 監査

- 各返答は、可能な限り `OperationPlan`（steps + reasons）と trace で説明可能であること。
- 「なぜその断片か」「どの糊を挿したか」が、自由生成ログではなく **選択と操作の記録** として残ること。

---

## 6. 非目標・後段

| 項目 | 扱い |
|------|------|
| ANN（HNSW 等） | 検索高速化のみ。完全制約とは独立。規模が要るまで不要（ロードマップ G8）。 |
| ニューラル編集器（LaserTagger 等） | 閉じた操作集合を保てるなら後段オプション。v1 契約の必須ではない。 |
| 自律収集・依存監査 | G8 以降。 |
| 出力 ⊆ 許可集合の機械検証 | G9。 |

---

## 7. 合意ログ（要約）

初期議論からの固定:

1. 接続詞等の閉じた集合は **操作として許容**（挿入ゼロにはしない）。claim 化までの締めは別途検討。
2. 合成単位はチャンクから始め、文／スパンへ分解する方向（実装済みの流れを契約として認める）。
3. 第一実装は規則／テンプレの決定的エンジン（ニューラル編集は後段）。
4. 履歴スパンのコピーは完全の許可集合に含める。

再収束合意（unify-workflow）:

5. ユーザー入力の処理は単一ワークフロー。
6. mode / generate トグルは本線の分岐にしない。
7. 本線は常に接地生成（as-is はその結果の一種）。
8. 連鎖デモ・eval は本線の連続呼び出しで表現する。

---

## 8. この契約の使い方

- 新機能・減枝・API 変更は、「単一ワークフローを壊さないか」「許可集合を増やしていないか」で審査する。
- 既存の G 系ドキュメントと衝突する場合は、**本契約を優先して G 系を更新**する。
